# Farmer dashboard

The CROPSY farmer dashboard is a client workspace at `/en/farmers/dashboard` and
`/bn/farmers/dashboard`. It is rendered inside the localized `(site)` layout and remains guarded by
the same `AuthProvider` and `AuthGate` used by the account pages.

The dashboard does not contain demo data. Every count, total, chart point, table row, coordinate,
map feature, weather observation, and AI answer comes from an authenticated Fastify API response.
Values that the API does not return are not displayed as facts.

## Access and role-based navigation

- A session must report the `FARMER` role. Other roles see a localized "Farmer role required" state.
- Navigation items are filtered by the `permissions` array from `/iam/auth/me`. A section is shown
  only when the session has one of its required permissions.
- Section permissions use the existing API matrix: `farms.read`, `cultivations.read`, `crops.read`,
  `expenses.read`, `harvests.read`, `listings.read`, `orders.read`, `ai.read`, `notifications.read`,
  and `profile.read`.
- The public header only shows the dashboard link to sessions with the `FARMER` role.

## Same-origin data proxy

Browser code never calls Fastify directly. `apps/web/app/api/dashboard/[...path]/route.js` forwards
allowlisted requests through `apps/web/lib/auth/server.js`, preserving the existing token policy:

- auth cookies stay HttpOnly and first-party;
- CSRF is derived server-side from the access JWT;
- token-shaped fields are stripped from JSON responses;
- only `GET` is accepted, plus `POST` for the AI ask/chat/recommendation and weather routes;
- unknown modules and mutation routes return `404`/`405` before reaching the API.

Profile reads/writes continue to use `/api/users/[...path]`. The client wrapper in
`apps/web/lib/dashboard/client.js` retries once after `/api/auth/refresh` on `401`.

## Statistics and honesty policy

- Counts are computed from API array lengths.
- Area, yield, expense, and harvest totals are summed only from numeric fields returned by the API.
- Mixed-currency amounts are listed per currency instead of being converted with invented rates.
- Charts use API-provided categories, series, and values, or client-side groupings of returned rows.
- Map geometry is drawn from API GeoJSON. There is no external tile provider and no sample
  coordinate baked into the app.
- Weather data is displayed only when the configured provider returns it. Provider or location
  errors are rendered as errors, never replaced with generated forecasts.
- There is no dedicated farmer inventory endpoint and no private notification feed endpoint. Those
  sections say so explicitly; Inventory shows marketplace availability, and Notifications shows only
  public module metadata.
- AI output is labeled with the API's own advisory, citations, and limitations. The dashboard does
  not invent agricultural advice.

## Localization

The dictionaries in `apps/web/lib/i18n/en.js` and `bn.js` keep identical leaf keys. API values with
`nameBn` fields are rendered in Bengali when the locale is `bn`; otherwise the English field is
used. Dates, numbers, and currencies use the matching `Intl` locale. Metadata, canonical URLs,
hreflang alternates, and Open Graph locale values are generated by
`createLocalizedPageMetadata(locale, 'farmersDashboard', '/farmers/dashboard')`.

## Responsive and accessible behavior

- Sidebar navigation becomes horizontally scrollable on small screens and sticky on desktop.
- Tables scroll horizontally rather than truncating API fields.
- Section navigation uses `aria-current`, and the map/charts expose `role="img"` labels plus
  screen-reader data tables.
- Loading, empty, and error states are localized. Failed requests expose a retry action.
- Profile edits are submitted through the existing profile API; no token is read from browser
  storage.
